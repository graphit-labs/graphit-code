# One gitignore entry — the project's runtime directory

## Objective

Three defects reported together, each one a generated artifact of the framework stating
something that is no longer what we want:

1. **The generated `.gitignore` ignored the whole brand directory.** A project's grammar
   overrides default to `.graphit/ast/queries`, so the one kind of customization that
   belongs to the *repository* rather than to the machine lived in the one directory the
   repository does not track. Rule overrides and dream reports were in the same position.
   `ast.queries_dir` existed as a way out, but it is a workaround for a wrong default.

2. **The AST skill mandated `graphit_ast_index` at the end of a change session.** Wrong
   tool: a session that changed code also wrote a task log and usually a memory, and those
   live in two other indexes. The mandatory end-of-session call is now `graphit_sync`.

3. **`line_numbers` had no declared default** on the two source-reading tools, so an agent
   reading the schema had nothing to tell it that `false` is the normal call. The behaviour
   was already `false`; the *contract* now says so.

## Implementation Details

### 1. The brand directory is split by ownership

The first attempt kept every path where it was and carved the exceptions out of the
`.gitignore` block with negations. That took six lines, and it does not reduce further —
gitignore cannot re-include anything beneath an excluded directory, so `.graphit/` plus
`!/.graphit/ast/queries/` never even consults the second line. The Engineer's call was to
invert it: **move the machine state down one level instead, and ignore only that.**

```
<project>/.graphit/
├── ast/queries/      grammar overrides          ─┐
├── rules/            rule and skill overrides    │ the repository's, committed
├── grammars/         grammar libraries           │ like any other file
├── dream/            reports and dream state    ─┘
└── runtime/          ← the only gitignored entry
    ├── daemon/       daemon.log, dream state file
    ├── cache/        skills/ and artifacts/ hash caches
    ├── mandate.hash
    ├── sync.stamp
    ├── sync.lock
    └── sync-heavy.lock
```

The block is now:

```gitignore
# --- GRAPHIT AUTOGENERATED IGNORER ---
**/.graphit/runtime/
# --- END GRAPHIT AUTOGENERATED IGNORER ---
```

**The `**/` prefix is load-bearing**, and this is the one non-obvious thing in the change.
A pattern with a separator in the middle is anchored to the directory of the `.gitignore`
that declares it, so a bare `.graphit/runtime/` ignores *this* project's machine state and
exposes that of every nested checkout, sub-project and test fixture below it. The old
one-line `.graphit/` had any-depth matching for free, because a pattern whose only
separator is trailing matches at any depth. The prefix buys that back.

New in `internal/brand` — the package that already names `DotDir` and the global
`RuntimeDir`, and needs nothing above it to produce any of this:

| Function | Purpose |
|---|---|
| `RuntimeSubdir()` | the name, `"runtime"`, in one place |
| `ProjectRuntimePath(projectDir, parts...)` | every writer of project-local machine state goes through here |
| `GitignoreContent()` | what `graphit init` injects |

`GitignoreContent` briefly lived in `internal/config`, because the six-line version had to
derive the carve-out from `DefaultASTQueriesDir()`. With the split it is pure naming, so it
moved down to `brand` and `config` lost the dependency.

Writers moved, all to `brand.ProjectRuntimePath`:

| Was | Now | Site |
|---|---|---|
| `.graphit/daemon/daemon.log` | `runtime/daemon/daemon.log` | `internal/daemon/project.go`, `internal/daemon/syncmodule.go` |
| `.graphit/daemon/<state>` | `runtime/daemon/<state>` | `internal/dream/dream.go` (`StatePath`) |
| `.graphit/cache/skills/…` | `runtime/cache/skills/…` | `internal/hub/adapters/ide/adapters.go` |
| `.graphit/cache/artifacts/…` | `runtime/cache/artifacts/…` | `internal/hub/adapters/ide/base.go` |
| `.graphit/.mandate.hash` | `runtime/mandate.hash` | `internal/hub/adapters/ide/mandate.go` |
| `.graphit/{sync.stamp,sync.lock,sync-heavy.lock}` | `runtime/…` | `cmd/graphit/commands/lifecycle.go` (`syncStateFile`) |
| `<project>/.graphit/<store>` (no-HOME fallback) | `runtime/<store>` | `internal/store/store.go` (`globalOr`) |

`mandate.go` also stopped hardcoding the literal `".graphit"`, which was the only brand
leak left in that path.

Deliberately **not** moved:

- **`dream/`** — the Engineer's call: a report is generated output, but whether it is worth
  committing is a judgement about that report, so the choice goes to whoever is looking at
  it. The consequence to know is that `dream_last_seen.json` is per-developer reading
  state and should not be committed; `dream.reports_dir` moves the whole vault for a
  project that wants the reports under `docs/`.
- **`grammars/{treesitter,antlr}`** — a search path the user populates, not framework
  output. Platform-specific binaries that a team may legitimately commit.
- **`ast/export`** — the default output path of an explicit `graphit ast export`; the user
  chose to produce it and can redirect it.
- **`rules/`, `ast/queries/`** — the whole point of the change.

The `.astignore` and `.wikiignore` defaults still exclude the **whole** brand directory
from indexing. Being versioned and being indexed are different questions: a grammar YAML
configures the parser rather than being parsed.

### 2. The end-of-session call — `internal/ast/rule.go`

Three sites: the `🔒 MANDATORY` section (heading, body, table, plus a new paragraph
answering *why sync, in the AST skill*), the `MandateTrigger()` always-clause, and the
trigger bullet. The preceding "Reindexing is automatic" section kept its table of targeted
`graphit_ast_index` fixes — still the right tool mid-session — and its heading changed from
*"do not call sync after editing code"* to *"after every edit"*.

`internal/knowledge/rule.go` gained a four-line note in its own "Reindexing is automatic"
section. Without it the two skills contradict each other: knowledge says never call sync in
the normal flow, AST now mandates one call at the end.

`graphit_sync` was **not** added to the AST module's tool inventory in the mandate: that
list is introduced as "MCP tools this module owns", and sync is a lifecycle tool. The
knowledge module already names sync in prose without listing it.

`internal/hub/rule.go` had a troubleshooting row claiming the default grammar directory is
gitignored, which is now false and would send an agent to configure `ast.queries_dir` for
no reason. It now points at the real remaining cause: the key was pointed elsewhere, and a
configured directory replaces the default rather than adding to it.

### 3. `line_numbers`

`astSourceInput.LineNumbers` and `wikiSourceInput.LineNumbers` now carry `(default: false)`
in their jsonschema description — the convention already used by `ai_optimized` and `wiki`
in the same files. No behavioural change: both handlers already passed the Go zero value
through, and `textslice.Apply` only formats numbers when the flag is true. Pattern matches
keep their line numbers regardless, since a match without its location is not an answer.

The AST skill's section 4b was retitled *"opt-in, off by default"*, so the example that
passes `true` reads as the exception it is.

## Use Cases

### UC-01: `graphit init` writes the ignore entry

- **Actor**: a developer running `graphit init`, or an agent calling `graphit_init`
- **Preconditions**: a project directory; `.gitignore` may or may not exist
- **Main Flow**:
  1. `newInitCmd` / the `graphit_init` handler resolves the project directory
  2. It calls `brand.GitignoreContent()`
  3. `git.InjectGitignore` writes the returned line between the brand markers, replacing
     an existing marked block or appending a new one
- **Alternative Flows**:
  - The file already carries the block: `InjectBlock` replaces it in place, preserving the
    surrounding user content
- **Error Scenarios**:
  - Write fails: the CLI reports a step warning and initialization continues — the entry is
    a convenience, not a precondition; the MCP tool ignores the error for the same reason
- **Postconditions**: `**/.graphit/runtime/` is ignored at every depth; nothing else under
  the brand directory is
- **Affected Files**: `internal/brand/brand.go`, `cmd/graphit/commands/lifecycle.go`,
  `internal/mcpstdio/tools_lifecycle.go`

### UC-02: a team commits a grammar override

- **Actor**: a developer adding a language override
- **Preconditions**: the project was initialized after this change, or `init` was re-run
- **Main Flow**:
  1. The developer writes `.graphit/ast/queries/go.yaml`
  2. `git status` shows it as an untracked file
  3. It is committed and reaches every other checkout, where the resolution chain reads it
     before the user's and the runtime's levels
- **Alternative Flows**:
  - The project prefers its grammars beside other tooling: `ast.queries_dir` still moves
    the directory, and it becomes a preference rather than a workaround
- **Error Scenarios**:
  - The project was initialized before this change: the old block still ignores
    `.graphit/` and the file stays invisible. Re-running `graphit init` replaces the block
- **Postconditions**: the override is versioned; machine state is still ignored
- **Affected Files**: `internal/brand/brand.go`, `internal/config/config.go`

### UC-03: the framework writes machine state

- **Actor**: the daemon, `graphit sync`, an IDE adapter, the dream runner
- **Preconditions**: a project directory
- **Main Flow**:
  1. The writer calls `brand.ProjectRuntimePath(projectDir, …)`
  2. It creates the directory if needed and writes inside it
  3. The file is covered by the single ignore entry, at any depth
- **Error Scenarios**:
  - The runtime directory cannot be created: each writer degrades as it did before —
    the daemon logs to a discard logger, the sync proceeds without its lock, the mandate
    fast path misses and rewrites
- **Postconditions**: no machine state exists outside `runtime/`
- **Affected Files**: `internal/daemon/{project,syncmodule}.go`, `internal/dream/dream.go`,
  `internal/hub/adapters/ide/{adapters,base,mandate}.go`,
  `cmd/graphit/commands/lifecycle.go`, `internal/store/store.go`

### UC-04: an agent finishes a session that changed code

- **Actor**: an agent
- **Preconditions**: source files were edited; a task log was written; memories may have
  been inserted
- **Main Flow**:
  1. The agent finishes the last edit and the documentation
  2. Before reporting the work done, it calls `graphit_sync` once
  3. Sync reindexes the AST graph, rebuilds the knowledge wiki, runs the memory cycles,
     syncs the Hub and reinstalls the IDE rules
- **Alternative Flows**:
  - Mid-session, only the code graph is suspect: `graphit_ast_index`, optionally with
    `path`, `grammar`, `reindex` or `reset`
  - Only the vectors are missing: `graphit_ast_embed`; only the wiki: `graphit_knowledge_sync`
- **Error Scenarios**:
  - A sync step skips its work: the tool returns the notes each step contributed rather
    than an unqualified success
- **Postconditions**: no index the session wrote to is left stale
- **Affected Files**: `internal/ast/rule.go`, `internal/knowledge/rule.go`

### UC-05: an agent reads source or a wiki page

- **Actor**: an agent
- **Preconditions**: the file is in the graph, or the page is in the wiki
- **Main Flow**:
  1. The agent calls `graphit_ast_source` or `graphit_wiki_source` without `line_numbers`
  2. The text comes back unprefixed
- **Alternative Flows**:
  - The line numbers are the point — reporting a location, aligning an entity with a range
    from the graph: pass `line_numbers: true`
  - A `pattern` was given: matches carry their line numbers either way
- **Postconditions**: the default read costs no extra width per line
- **Affected Files**: `internal/mcpstdio/tools_ast.go`, `internal/mcpstdio/tools_wiki.go`,
  `internal/ast/rule.go`

## Test Cases & Acceptance Criteria

### Feature: the generated ignore entry
Ref: UC-01, UC-02, UC-03

`TestGitignoreContentIgnoresTheRuntimeDirAtAnyDepthAndNothingElse`
(`internal/brand/gitignore_content_test.go`) asserts against **real git** rather than by
string comparison. The difference between ignoring this project's machine state and
ignoring every nested project's instead is one `**/` prefix that reads as decoration; only
git can say which of the two was written.

#### Scenario: machine state is ignored
```gherkin
Given a git repository whose .gitignore holds the generated entry
  And files under ".graphit/runtime/" — a daemon log, both hash caches, the mandate hash, the stamp and a lock
When "git status --porcelain --untracked-files=all" runs
Then none of them is listed
```

#### Scenario: the repository's half of the brand directory is visible
```gherkin
Given a git repository whose .gitignore holds the generated entry
  And files at ".graphit/ast/queries/go.yaml", ".graphit/rules/ast.md", ".graphit/dream/01ABC.md" and ".graphit/grammars/treesitter/go.so"
When "git status --porcelain --untracked-files=all" runs
Then all four are listed as untracked
```

#### Scenario: a nested project's machine state is ignored too
```gherkin
Given a git repository whose .gitignore holds the generated entry
  And a file at "internal/pkg/.graphit/runtime/daemon/daemon.log"
When "git status --porcelain --untracked-files=all" runs
Then it is not listed
```

### Feature: machine state is written under the runtime directory
Ref: UC-03

#### Scenario: the daemon creates its log directory there
```gherkin
Given a project supervisor started for a project directory
When it opens the project log
Then the directory "<project>/.graphit/runtime/daemon" exists
```

#### Scenario: the sync stamp is written there
```gherkin
Given a project directory
When stampSync runs
Then "<project>/.graphit/runtime/sync.stamp" holds an RFC3339 timestamp
```

Covered by `TestProjectSupervisor_Start_CreatesLogDir` (`internal/daemon`) and
`TestStampSyncCreatesTheRuntimeDir` (`cmd/graphit/commands`), both updated from the old
paths.

### Feature: line numbers are opt-in
Ref: UC-05

#### Scenario: an unset flag leaves the text unprefixed
```gherkin
Given a request with LineNumbers false
When textslice.Apply slices the text
Then the result carries the lines joined as they were, with no numeric prefix
```

#### Scenario: a tail keeps absolute numbers when asked
```gherkin
Given a request with Tail 2 and LineNumbers true
When textslice.Apply slices the text
Then each returned line is prefixed with its number in the original text
```

Covered by `TestApplyTailKeepsAbsoluteLineNumbers` (`internal/textslice`), which predates
this change and pins the opt-in half.

## Trade-offs & Decisions

**Splitting by ownership instead of negating.** The six-line block worked and was tested,
including the nested case. It was rejected as too much machinery for the result, and the
Engineer's alternative is better on every axis: one line, no ordering rules, and the
question "is this file mine or the framework's" answered by where it sits rather than by a
pattern list. The cost is that paths moved, which is a one-time migration.

**Existing checkouts are not migrated.** `InjectGitignore` is an `init`-time call and was
left that way. Adding it to `graphit sync` would refresh every project automatically and
would also re-add the block to a project that deliberately removed it. Nothing under the
old locations is worth keeping — caches, locks, a stamp, a log — except `.graphit/dream/`,
which stays where it always was and is unaffected.

**`dream/` stays out of `runtime/`.** Explicit call by the Engineer: leave the judgement to
the user. It means the per-developer `dream_last_seen.json` is now visible in `git status`,
which the dream spec now says out loud.

**`sync` is not in the AST module's tool inventory.** The mandate introduces that list as
tools the module *owns*, and sync is a lifecycle tool. It is named in prose instead, which
is how the knowledge module already refers to it.

## Technical Debt

- [ ] A project initialized before this change keeps the `.graphit/` block, so its grammar
  and rule overrides stay invisible with nothing reporting it. A check in `sync` that
  **warns** when the marked block is the old form — without rewriting it — would close the
  gap without taking the decision away from the project.
- [ ] `.graphit/ast/export` is still the default output of `graphit ast export`, so a
  generated export lands in a tracked location. Harmless (it only exists if someone asked
  for it) but inconsistent with everything else generated.
- [ ] `docs/tasks/centralize-stores-in-global-dir.md` records the end-of-session mandate as
  `graphit_ast_index`. It is a historical log and was left alone; a reader who finds it
  first will read a superseded instruction.
- [ ] Several help strings still describe project-local `.graphit/knowledge/` and
  `.graphit/memory/` directories that the store centralization removed
  (`cmd/graphit/commands/{knowledge,memory}.go`, `completions.go`,
  `internal/uiserver/wiki_handler.go`). Pre-existing, unrelated to this change, and now
  slightly more visible because the brand directory is documented as tracked.

## System Knowledge

- **A gitignore pattern whose only separator is trailing matches at any depth; one with a
  separator in the middle is anchored.** `.graphit/` ignores `internal/x/.graphit/` too,
  `.graphit/runtime/` does not, and `**/.graphit/runtime/` does again. Any change to an
  ignore pattern must be checked with `git status --porcelain -uall` on a tree that
  actually contains the nested case — this bit the first attempt.
- **Re-including a path under an excluded directory is impossible, but re-including the
  excluded directory itself is not.** `!/.graphit/` after `.graphit/` works, because
  `.graphit`'s parent is the root. That is the only reason the six-line form was legal at
  all, and why the negation approach cannot be shortened below it.
- **`git.InjectBlock` trims the content and wraps it in markers**, so multi-line content
  needs no special handling and re-injection replaces the previous block while preserving
  up to two blank lines on either side.
- **`textslice.Apply` composes in a fixed order** — line range, head, tail, pattern — and
  returns early on `pattern`, so `line_numbers` is only consulted on the non-pattern path.
- **The generated `SKILL.md` and `AGENTS.md` in the working tree come from the installed
  binary, not the source tree.** Editing `rule.go` changes what a future `make install` plus
  daemon cycle writes; it does not change the files on disk in this checkout.
- **`internal/memory/.graphit/` in this repository was a stale leftover** from an older
  binary, not something the current tests create — verified by deleting it and re-running
  `go test ./internal/memory/`. The old blanket `.graphit/` pattern had been hiding it.
