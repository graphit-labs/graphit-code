# Hook-delivered mandates and Hub rules

## Objective

Stop materializing Graphit's mandate in `AGENTS.md`/`CLAUDE.md` and stop copying installed Hub `rule` artifacts into IDE-specific rule directories. Compose both sources dynamically when the native lifecycle hook runs, while leaving skills installed and lazy-loaded exactly as they are.

The hook becomes the single delivery path for resident Graphit instructions. It must use the current project configuration and lockfile on every new session, preserve user-owned instruction files and rules, cover the existing resume/compaction/subagent boundaries, and retain native-tool fallback when Graphit tools are unavailable.

## Plan & Task Breakdown

- [x] **T1 — Define the dynamic instruction contract** — Specify deterministic ordering, module enablement, Hub rule loading, empty/error behavior, and the split between bootstrap and lightweight reinjection.
- [x] **T2 — Compose context at hook execution time** — Load enabled module mandates and installed Hub rules from the active project and append them to the hook protocol without injecting skill bodies.
- [x] **T3 — Stop materializing mandate/rule files** — Remove the write paths for Graphit mandates, Hub rules, and the Claude/Gemini markdown bridges. Delete the generated files tracked in this development repository without adding legacy migration logic.
- [x] **T4 — Preserve lifecycle coverage** — Deliver the dynamic context at main-session and subagent starts; keep repeated model-boundary reinjection compact where the full context has already been established.
- [x] **T5 — Test migration and ownership** — Cover all adapters, disabled modules, installed rules, sync cleanup, user-file preservation, payload formats, and idempotency.
- [x] **T6 — Update architecture and durable memory** — Record the new ownership boundary, run focused/full validation, synchronize Graphit indexes, and regenerate tracked adapter artifacts.
- [x] **T7 — Make hook project resolution machine-independent** — Remove machine-specific absolute roots from committed hook configuration; resolve the active project from native hook input or execution cwd, retain an explicit override only for diagnostics, update tests/docs/memory, sync, and commit the correction on `main`.
- [x] **T8 — Document host activation per adapter** — Replace the generic trust/enabling caveat with user-facing steps for every supported adapter: required action, verification path, reload boundary, and any surface-specific limitation.

## Decisions

- Skills remain physical IDE artifacts because hosts discover and load them on demand.
- Commands and agent artifacts are outside this change.
- Only Graphit-owned mandate blocks and Hub artifacts whose lockfile type is `rule` move to hook context.
- Hook execution reads current state instead of embedding instruction text into hook configuration, so an artifact/config update is visible to the next lifecycle event without rewriting an instruction markdown file.
- Failure to load dynamic context must not block the host: the compact Graphit invariant and native fallback remain available.
- This is a development-only clean break. Runtime sync will not scan for or migrate files generated by older builds.
