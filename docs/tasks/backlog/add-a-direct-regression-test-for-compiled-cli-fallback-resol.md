# Add a direct regression test for compiled CLI fallback resolution

The investigation recorded in `docs/tasks/confirm-default-ide-cli-resolution.md` proved from `internal/config/config.go` that `ResolveCLI` calls `ResolveConfig("cli", ...)`, so a `cli=...` entry in `CompiledDefaults` is consulted before the IDE-derived and terminal fallbacks. Existing coverage is indirect: `TestResolveConfig` proves generic compiled defaults, while `TestResolveIDEAndCLI` proves CLI mapping and terminal fallback. Add a focused test in `internal/config/config_default_test.go` that isolates HOME and `GRAPHIT_CLI`, resets `parsedDefaults`/`defaultsOnce`, sets `CompiledDefaults = "ide=cursor,cli=custom-cli"`, and asserts `ResolveCLI("", nil, nil, "claude") == "custom-cli"`. Also assert that an explicit/global/env CLI still outranks the compiled entry and that, with `cli` absent, the resolved IDE mapping is used. Preserve and restore all package globals so the test is order-independent. Acceptance: `go test -count=1 ./internal/config` passes and the chain is explicitly guarded against regression.
