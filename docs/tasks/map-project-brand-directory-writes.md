## Decision Rationale

- `ast export` and Dream output are generated, so their defaults live under
  `.<brand>/runtime/**`. Explicit output configuration remains user-owned.
- `rules/<module>.md`, `rules/<module>_skill.md`, and `ast/queries/<language>.yaml`
  are textual project configuration and remain visible to Git.
- `grammars/{treesitter,antlr}/**` remains the supported project-local parser-binary
  tier, but is ignored because its files are platform-specific. Shared binaries travel
  through Hub language artifacts.
- `brand.GitignoreContent()` is the only source of the two generated patterns; the
  marked checkout block and Git-real tests consume that contract.
- Legacy `.graphit/ast/export/**` and `.graphit/dream/**` data is preserved in place.
  Automatic migration or deletion would risk destroying user-selected output.

## Implementation Details

- `brand.GitignoreContent()` emits the two any-depth patterns consumed by project init.
- `brand.ProjectRuntimePath` supplies the default AST export and Dream vault paths.
- Dream path consumers use `ReportsDir`, including prompt text and user-facing help.
- Canonical architecture, Git, AST, Dream, config, backlog, CLI, getting-started, ignore,
  and user-manual documentation now describes the same ownership boundary.
- The ADR records why parser binaries are local while rules and query YAMLs are shared.

## Use Cases

### UC-01: Initialize the generated Git boundary
- **Actor**: Developer running `graphit init`.
- **Preconditions**: The target project is writable and may already have a `.gitignore`
  with or without a marked Graphit block.
- **Main Flow**:
  1. `graphit init` requests the content from `brand.GitignoreContent()`.
  2. `InjectGitignore` inserts or replaces the marked block.
  3. Git ignores `runtime/**` and `grammars/**` at the project root and below nested projects.
- **Alternative Flows**: Re-running init replaces the block idempotently; unrelated user
  patterns remain untouched.
- **Error Scenarios**: A read-only `.gitignore` returns a write error and leaves the
  existing content intact.
- **Postconditions**: Rules and query YAMLs remain visible; runtime and parser binaries do not.
- **Affected Files**: `internal/brand/brand.go`, `internal/git/git.go`, `.gitignore`.

### UC-02: Export AST output
- **Actor**: Developer running `graphit ast export`.
- **Preconditions**: The project AST exists and the selected output directory is writable.
- **Main Flow**:
  1. The command defaults `--output` to `.<brand>/runtime/ast/export/`.
  2. The exporter writes the chosen Obsidian or bundle representation there.
- **Alternative Flows**: An explicit `--output` writes exactly to the caller-selected path.
- **Error Scenarios**: An unwritable destination returns an export error; no fallback path
  silently changes ownership.
- **Postconditions**: Default output is ignored; explicit output follows the Git policy of
  its selected location.
- **Affected Files**: `cmd/graphit/commands/ast.go`.

### UC-03: Produce and read Dream artifacts
- **Actor**: Dream runner, CLI user, MCP client, or UI user.
- **Preconditions**: Dream is enabled for production; report listing itself may run while
  Dream is inactive.
- **Main Flow**:
  1. `ReportsDir(projectDir)` resolves the vault.
  2. Without configuration it returns `.<brand>/runtime/dream/`.
  3. Reports, `.exhausted` sentinels, and `dream_last_seen.json` use that vault.
  4. Prompts, CLI help, MCP, and UI display the same resolved path.
- **Alternative Flows**: `dream.reports_dir` replaces the default, including a versioned
  location such as `docs/dream` or the legacy `.graphit/dream` during migration.
- **Error Scenarios**: An unwritable configured directory returns the existing filesystem
  error; the runner does not redirect output silently.
- **Postconditions**: Default Dream output is ignored, while publishing is explicit.
- **Affected Files**: `internal/dream/reports.go`, `internal/dream/prompt.go`,
  `cmd/graphit/commands/dream.go`, `internal/uiserver/`.

### UC-04: Customize project parsing and agent rules
- **Actor**: Developer adding project-local parser or instruction customization.
- **Preconditions**: The project has been initialized.
- **Main Flow**:
  1. Query YAMLs go under `.<brand>/ast/queries/` and rules under `.<brand>/rules/`.
  2. Git sees both trees for team review and distribution.
  3. Local Tree-sitter/ANTLR binaries go under `.<brand>/grammars/`.
  4. Git ignores the binary tree while grammar resolution continues to prefer it.
- **Alternative Flows**: A shared grammar binary is packaged and distributed as a Hub
  language artifact; user-global grammars apply across projects.
- **Error Scenarios**: A missing or incompatible local binary falls through or reports the
  existing grammar-loading error; ignoring it does not disable the resolution tier.
- **Postconditions**: Textual configuration is reproducible and local binaries remain local.
- **Affected Files**: `internal/brand/brand.go`, `internal/ast/` grammar loaders.

## Reflection

- The storage resolver is also the source of truth for prompts, CLI help, and fixtures; moving only the writer leaves an operationally incorrect path even when the file lands correctly.
- Repeated path snippets in tests require function-scoped patches and immediate diff inspection; broad context caused one false diagnosis during this task.
- No new IDE artifact was warranted: the storage-audit workflow is already captured by the existing Graphit skills and the updated persistent memories.

## Key Decisions

- Start from the project knowledge and memory indexes, then verify the write paths and their callers through the AST graph.
- Treat `<brand>` as the build-time brand name (for example, `.graphit`) and report paths using the generic notation requested by the user.
- Separate automatic machine-state writes from repository-owned paths and explicit command outputs; they have different version-control semantics even though all are writable.

## System Knowledge

- Project-local runtime writers use `brand.ProjectRuntimePath`; the grammar-binary tree
  is the deliberate second ignored ownership class.
- `ReportsDir` is a behavioral boundary shared by writers, readers, prompts, CLI, MCP,
  and UI. Reconstructing its default elsewhere creates drift when configuration changes.
- `store.globalOr` may place normally global AST/wiki/memory stores under project runtime
  only in the degenerate no-home fallback; normal machines keep those stores global.
- Git ignore and AST ignore answer different questions: the entire brand directory stays
  out of the code graph even though rules and query YAMLs remain versionable.

## Trade-offs & Decisions

- Two generated patterns were chosen over ignoring the entire brand directory with
  negations, because Git cannot re-include descendants of an excluded parent reliably.
- Project grammar binaries remain supported but local. This sacrifices accidental Git
  distribution in favor of platform correctness and explicit Hub packaging.
- Legacy output is not auto-migrated. Avoiding destructive or ambiguous moves outweighs
  convenience; overrides provide a controlled migration path.
