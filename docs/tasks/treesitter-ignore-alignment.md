# Ignore treesitter vendored parsers (like ANTLR)

## Problem

The `parser.c.inc` files located in the directories of four Tree-Sitter grammars
(Clojure, GraphQL, ObjC, R) are C parsers generated by Tree-Sitter, vendored because
their respective packages do not publish official Go bindings.

GitHub Linguist misidentified them as **Pawn** because of the `.inc` extension,
misleadingly inflating the repository's language statistics.

Moreover, these files were not being ignored by the AST indexer or by GoLangCI-Lint,
unlike the ANTLR-generated files, which already had those exclusions.

## Solution

### `.astignore`
Added the rule `internal/ast/treesitter/*/parser.c.inc` to exclude the vendored files
from AST indexing. The `binding.go` (Go integration code) continues to be indexed
normally.

### `.gitattributes` (new file)
Created with `linguist-vendored=true` for all `parser.c.inc` files:
```
internal/ast/treesitter/*/parser.c.inc linguist-vendored=true
```
This causes GitHub Linguist to exclude those files from its language calculation for
the repository (the same effect as `vendor/`).

Also took the opportunity to mark ANTLR-generated files (`.interp`, `.tokens`) as
`linguist-generated=true`.

### `.golangci.yml`
Added `internal/ast/treesitter` to the exclusion block `paths` of GoLangCI-Lint,
mirroring the treatment already in place for `internal/ast/antlr`.
