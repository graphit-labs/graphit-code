# Rust generic Tree-sitter semantic model

This page records the execution contract and Linux qualification for delivery B. Native preparation, retained collection, names, entity/value/owner
assembly, export/complexity/relations, embedded preparation and retained code
projections are written in [tree_sitter_generic_model.rs](../../crates/graphit-ast/src/tree_sitter_generic_model.rs).
The six affected AST executables passed in run 29c, including all 36 Generic
cases and the stock-profile controls. Two final focused regressions then passed
in run 29l. Main Graph/FTS acceptance passed in run 29m; affected Rust quality
passed in runs 29q and 29u. Historical failures and current evidence are recorded below. NativeNN is the separate delivery C.
The existing specialized models remain active.

## Retained native collection

The generic factory receives an effective profile and its genuine
`PreparedTreeSitterContexts`. It reuses the compiled capture-role indices through
`prepared_profile().query_roles()`; it does not compile the same query again.
A configured role absent from the compiled query is a typed preparation error.
An optional capture missing in an individual match remains a separate observation.
Regular expressions for `name_reject` are compiled during preparation. Neither
factory preparation nor these borrowed metadata accessors retain its Original.

Collection receives the actual `PreparedInput`, relative path components and
existing `IdentityLimits`. The parsed owner retains the native context collection,
identity document, original source and a borrow of that input, including its
origin plan and request context. The caller keeps the input and its mapping alive
until all consumers finish. The factory can be dropped after collection; the
native tree and compiled queries remain owned by the collection.

Getters check the retained Original. Node identities must belong to that tree;
parents must precede and contain their children. Original projections come from
that same input. An unrelated catalog cannot be substituted even when its text
is equal. Reserved specialized languages are rejected by this generic route,
including a reserved language paired with a foreign grammar. This includes the
six specialized Tree-sitter languages, JSON and reserved ANTLR language routes.

## Lexical names and Data views

Only slots bound to the configured name role can produce a name. Empty
`name_capture` means `@name`, as in the raw collector. There is no search through
all captures when that role is missing. Name rejection examines the original
lexeme before the display view. Non-exact origins or recovered syntax do not
become exact names. Independently of entity matches, `syntax_recoveries()` retains
every SDK error or missing node with its native identity, kind, prepared range
and original projection. Graph diagnostics serialize this evidence, so a parse
with no entity capture can still report native recovery.

Identifier names retain the UTF-8 lexeme without Unicode canonicalization or
identifier decoding. Data is selected by `name_is_data`, or a configured value or
parent capture. Its searchable view removes one matching outer pair of single,
double, backtick or triple quote delimiters, longest pair first. It does not
interpret escapes. Both raw and interior ranges still refer to the original
allocation. Blank, multiline and Data names exceeding 256 Unicode scalars retain
an explicit rejection reason. This is the published Data-name eligibility rule,
not a new runtime quota.

The isolated entity assembly preserves each occurrence and merges only equal
`(uid, data_key)` contributions. UID subjects remain the original anchors.
Values become named Value nodes with `CONTAINS` and a String-valued property on
the owner; labels do not select a literal decoder. Multiplicity is associated by
unambiguous native containment, never positional zip or Cartesian product.
Conflicting values, spans and owners remain observable. An omitted declaration
role stays NotConfigured in its contribution and does not contradict a separate
native declaration proof. Distinct proven native declaration units do conflict;
Invalid/Conflict contributions keep their explicit unavailability. Staged stock profiles
explicitly set `name_is_data` consistently for bare and value-bearing queries
sharing `(graph_label, data_key)`, preventing incompatible name representations
for the same subject. This is profile policy rather than runtime normalization.
Ruby/Swift query string literals containing escaped double quotes in single-quoted
YAML scalars receive explicit syntax repairs before SDK qualification.

## Extents, owners and native policies

A full extent requires an explicit native `span_capture` containing the name.
Missing evidence remains Missing; an arbitrary capture parent, hull or clamped
range is not a full entity. All thirty-three stock extra profiles have active annotations and expected-span
fixtures; their 33-sample fullspan case passed in run 28r. C/C++ initialized variables capture their full declaration; Kotlin
and Swift fields capture the inner property rather than the surrounding class
body. Dart uses explicit top-level, external, local, method and bodyless-member
wrappers, following the pinned official grammar. Signature-only nodes do not
prove the body extent. The 41-grammar/40-profile acquisition and parse/query
qualification does not prove those semantic expectations.

The declaration used by policies is distinct from the published span. The revised
contract requires an explicit `declaration_capture` whose native unit matches
`declaration_types`. A generic kind alone is not proof of a declaration: Clojure
uses `list_lit` for both definitions and conditionals, and Elixir uses `call` for
definitions, signatures and conditionals. Missing capture evidence remains
NoDeclaration; there is no nearest-ancestor or LCA fallback. This role is published in the shared profile contract; its generic consumer is
activated; the scope-role consumer passed its native fixtures in run 29c. Explicit parent bindings precede native
contexts and do not fall back when missing or ambiguous. Otherwise scopes use
outer-to-inner order for identity, retaining self-exclusion. Context labels do
not replace actual query entity labels; for example, an HCL Resource context can
contain a Variable entity. Incomplete chains remain explicit and cannot qualify
an exact code projection.

The optional profile list `context_requires_entity` restricts polymorphic
context kinds, with an empty default. Every listed kind must occur in
`context_types`, otherwise preparation returns a typed policy error. For those
kinds, only an actual Entity candidate with the same native name/span/declaration
can establish the context; a namespace synthesized from another context cannot.
Failure preserves an incomplete chain. This optional custom assertion is tested
with genuine JSON scopes. R and Elixir use explicit entity scopes instead of broad
polymorphic kind maps. Other configured kinds retain namespace identities without Entity queries,
including the C# namespace/class control fixture. Under `merge: true`, the list follows normal profile inheritance, replacement,
empty-list clearing and original provenance.

The optional Query `context_capture` selects SDK scopes explicitly owned by an
Entity, including a function body whose name is outside that body. An exact native
span or declaration unit must contain both name and scope. Multiple names and
scopes associate only through unambiguous native containment and physical identity;
there is no positional zip. Missing, invalid, recovered or ambiguous scopes retain
diagnostics/conflicts. The role retains capture slots and NodeIDs, not copied text.
Explicit scopes work even with empty `context_types`. R Function queries own
`function_definition`; Elixir Function/Module queries own their declaration unit.
Arithmetic and ordinary calls therefore do not invent namespaces or owner barriers.

Owner chains, relation sources and complexity consume the same scope evidence.
The nearest owned scope establishes a relation source before physical declarations;
multiple actual endpoints remain ambiguous. A namespace without Entity or an
unresolved anonymous scope cannot fall through to an outer or embedded host.
Complexity includes only explicitly owned anonymous bodies and cuts nested named
declarations and unclaimed anonymous bodies. A direct Clojure anonymous child is
still nested; its parent relationship alone proves no ownership. Configured native
namespaces without Entity queries remain supported, including C# namespace/class.

The declaration/complexity traversal consumes explicit roles.
Matching profile/catalog/role changes and their native fixtures passed in run 29c. Metric boundaries use actual
declaration captures from Entity matches and configured anonymous-function kinds,
so ordinary nested list/call decisions are counted.
B's executable Task also defines the seven export strategies, native declaration
headers, lexical relation resolution and complexity rules, including Clojure and
Elixir `head_calls`. These are required implementation, not capabilities proved
by the raw collector. Policy outcomes must preserve absence, ambiguity and
recovery instead of using spelling or a Rust/Go default as a generic binder.

For each relation kind, effective labels union all sibling Relation query
`target_labels` and the matching `TargetRule.labels`. An empty union uses declared
Entity graph/value labels. Specialized executors keep their own target policies.
A configured fallback can change the allowed target label but preserves the same
native qualifier, owner and lexical scope. An unknown qualifier cannot reach a
homonym in another scope through fallback. A focused correction and four new
fixtures for these branches passed in run 29c.

Embedded text owns its transformed bytes and exposes a prepared input only while
that owner is alive. Original mapping uses the existing Direct, MappedAtom,
removed-original and Synthetic-wrapper primitives. Literal replacements run once,
longest key first with lexical ties, followed by validated numeric references
and then wrappers. Invalid references remain raw with a diagnostic. A claimed
body with an unmapped explicit language is not recaptured by a generic fallback.
A repeated profile/grammar/body interval without progress reports a cycle.
The raw SDK match remains the sole owner of its captured text. Selected body
metadata keeps the actual node identity and borrowed prepared/original ranges;
selection filters before constructing metadata and does not clone body text.
The owning transform exposes `with_input` so consumers cannot retain a child
input after its text/mapping owner is dropped. Cropping a mapped atom partway or
replacing mixed original/synthetic provenance returns an explicit unavailable
outcome rather than inventing a coordinate mapping. Empty anchors are preserved
as ambiguous candidate sets. `OriginalProjection::Exact` means one original
interval, including a complete `MappedAtom`; it does not establish byte identity.
Only `Direct` validates identical bytes. Consumers keep `origin_plan()` evidence
and never promote Compound/Synthetic/Ambiguous/Unmappable projections to Exact.
Numeric-reference diagnostics retain offsets in the
normalization input phase; those offsets are not claimed as final source ranges.

These configured transforms are part of B; the existing PostgreSQL-to-PL/pgSQL
route remains a separate specialized producer.

## Consumers and qualification boundary

The isolated assembler feeds the existing owned `AstSemanticGraphBatch`, Graph publication and
`EntitySearch` encoder using genuine Raw/Source association. Its App composition
is activated together with the model export. Coordinated build 28r compiled
AST, App and both new test targets. Its functional results are preserved below;
Main qualification remains separate from the six released AST executables. Embedded factories are cached per loaded
profile, and inventory access revalidates retained profile sources. A child batch
can merge only with the same Source association. Source-less resolved relations
can use only a uniquely containing native host, restricted by configured host labels.
Merged embedded outcomes retain their child-local relation/source/capture/node
ordinals and record the embedded selection as provenance. A source ordinal is not
a position in the merged entity-node vector. The FILE metadata is rebuilt using
the shared observation encoder, so its resolution shape remains consistent.
`AstGraphEmbeddedComposition` accumulates diagnostics and capabilities during the
real App recursion and serializes them at `finish`, rebuilding FILE once after
all host blocks. Each merge preserves child-local addresses without reparsing
or serializing the accumulated host observations.
No new store or FTS schema is introduced. Its Main fixture overrides the shipped
TOML extraction profile in the user layer, using linked `tree-sitter-toml` for
`.native` files. It requires actual Graph/FTS results, source hashes, versions,
ranges and cleanup.

C consumes the retained native document through `NativeNnGenericInput` and
`encode_native_nn_generic`, rather than serialized Graph. The Arrow contract is
`ast-native-nn-4` with the same 21 fields and nullable `model_generation` for
remote embeddings. Older schemas require ordinary derived reindexing under the
[shared contract](rust_tree_sitter_native_nn.md#embedding-providers-and-optional-query-reranking).
Generic entity and owner names use
`NativeSource`: `name` and `raw_name` equal the original anchor lexeme.
Graph Data display remains separate and correlates through UID/data_key and
Source SHA. Specialized Identifier/LiteralSource/JsonName/RustType validators
remain active. Reserved language/grammar mismatches cannot enter Generic;
tag 2 has no compatibility reader and requires normal derived reindexing.

`GenericEmbeddedInput::with_input` keeps origin segments, anchors and PreparedInput
alive for its synchronous consumer. Input construction checks the same Original;
App composition also rechecks it after each child, including a failed child.
Graph assembly and optional NN projection preparation use one synchronous
traversal that retains all parse owners. Embedding, reuse and publication retain
their existing asynchronous APIs outside this parser traversal.

`owner_frames(entity_index)` exposes the complete native identity chain in
outer-to-inner order, including configured namespaces without Entity queries.
Each borrowed frame contains its label, original raw anchor, optional exact
extent and conflicts. `code_projections` rejects missing/conflicting owner
extents; the codec never truncates the chain. A namespace whose original name
is Exact may retain its SDK-backed Graph identity even when the original unit
is NonExact. That unit remains typed and diagnosed as
`NonExactContextExtent`; NN reports `OwnerExtentUnavailable` instead of
inventing a range. This explicitly expands the earlier Graph eligibility rule
that discarded such namespace identities.

Exact original projection means one original interval, including a complete
MappedAtom. For `&#x03B1; → α`, NN keeps `&#x03B1;` and its original anchor;
it does not substitute prepared `α` or require Direct bytes. NonExact,
Compound, Synthetic and Unmappable observations remain unavailable.
