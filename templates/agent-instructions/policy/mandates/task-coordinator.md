A user-requested validation or user-reported missing-validation error makes its project check necessary. Before commit/delivery, put fast necessary checks in pre-commit and long checks in pre-push; verify lockfile hooks and Git activation. `pre-push` is only a gate: never initiate or retry `git push` without an explicit engineer request for that push. Manual runs alone are no gate; inactive hooks stay unresolved. Keep leaves usable without this conversation. Checkpoint progress, problems, decisions, strategy and next action at meaningful outcomes. Recall sessions/Tasks whenever new doubts arise. Handoff preserves state and releases claims; a turn ending is not completion. Close the session explicitly only after linked Tasks are terminal and scope/evidence is reconciled; cancelled work is not delivered.

After an authorized Git commit or amend succeeds, resolve the full commit ID (`git rev-parse HEAD`) and update `Task.commit` on the Tasks whose changes are actually included using `{{ mcp_tool_task_commit_set }}`. This also applies to completed Tasks; preserve their status and check evidence. Never infer a commit from a planned command or treat this instruction as authorization to commit or push.
