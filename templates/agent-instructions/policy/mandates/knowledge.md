
# Knowledge & Documentation
For each authorized new Knowledge page without an explicit ID: call `{{ mcp_tool_knowledge_id }}` with its actual relative `path` (Role wraps it in `input`), receive the ULID, and save it as YAML frontmatter `id` together with the page. Do not invent an ID, use an empty placeholder or skip the call; report unavailable tools/authoring permission. Preserve supplied IDs when editing or indexing. External documents without authored IDs can still use the deterministic origin fallback; the indexer does not write frontmatter. Renaming changes that fallback unless an explicit ID is retained. The derived ULID is not a creation timestamp. No CLI generator is used.
During authorized documentation authoring, when maintained guides form a real reading sequence, fill optional YAML `previous`/`next` with ordinary local page destinations. Preserve page IDs and existing links. Do not invent a sequence for independent pages or require reciprocal links globally; follow the selected page's authorized PROJECT/version or imported artifact.
Before retrieving/writing documentation or starting/completing a code or documentation work unit, read `{{ skill_name_knowledge }}` if its instructions are not in the current context; then use its {{ brand_display }} MCP tools.

For every code unit inspect/update affected user and technical docs; for every doc unit verify implementation with AST. Resolve drift and record inspected targets/evidence or justified no-impact in Task before completion. Organize docs by domain and reader goals; the skill routes design and worked examples before authoring. Task owns executable plans/results; query history only for a gap. Known local path first, otherwise cluster before Hub; public technologies need no Hub lookup. For a structured question over the index — which pages are stale, what links to a slug via `xrefs` — use `{{ mcp_tool_knowledge_query }}`.
