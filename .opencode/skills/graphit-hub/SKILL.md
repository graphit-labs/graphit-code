# Graphit Hub

`project_dir` is a runtime MCP argument, not persisted project identity. In docs, Task, Memory and handoffs save project identity plus repository-relative paths; never copy a machine-specific checkout root. Resolve the local root again on each host. Stores follow the checked-out project version (Git branch; `main` without Git); optional `project_version` reaches another.

Persistence boundary for every module: shared project records may contain only non-sensitive content inherent to the project and needed for confirmed contracts, decisions, evidence, operations or technical continuity. Never persist personal or sensitive user/organization data, secrets, credentials, security-risk material, or an engineer's feelings, frustration, transient impressions or unconfirmed speculation. User-only context belongs only in private user memory when it is a durable, legitimately useful preference or correction; otherwise do not persist it. Keep necessary technical hypotheses explicitly labelled and never promote them to facts.

Use this skill for named ecosystem projects, Hub artifacts and Graphit configuration. Public libraries, frameworks and APIs do not require Hub discovery; use their official documentation when current details matter. Honor an explicit artifact request and reuse verified identities and versions.

## Resolve, select, read

Before unfamiliar project discovery, artifact selection or local removal, read [discovery through useful evidence](references/discovery-cases.md). Reuse that reference for related calls. If unavailable, call `graphit_module_skill` with `module: hub`, `reference: references/discovery-cases.md` and the known `project_dir` when applicable.

1. Resolve a named ecosystem project with `graphit_projects_list` in the initialized current project. Returned neighboring checkouts are Graphit-managed: use their authorized `checkouts[].dir` as `project_dir` for module tools, and read their relevant skill/overrides. Explore code through AST and contracts through Knowledge. Do not substitute native repository walks or invent local paths from a remote project ID.
2. If no local match exists, use `graphit_hub_projects` with the explicit configured transport/provider and pagination. Optional `id` or literal `name_prefix` selects projects; they are mutually exclusive. A returned `{id,name}` is discovery metadata, not PROJECT, storage or content authorization. Missing results and unavailable service are different outcomes.
3. Use `graphit_hub_search` for one explicit remote `producer` PROJECT. Optional `artifact_type`, `id` and `version` are literal filters; there is no free-text `query`, wildcard ID or separate metadata-show call. Inspect returned names/descriptions/tags within relevant pages. A version filter selects manifests containing that exact version while retaining their full versions list and declared optional latest; never infer a latest value. Follow `next_cursor` with the same selection. An authorization revision change requires a fresh first page.
4. Choose the actual installer for that kind. `graphit_hub_install_native` installs one exact AST or Knowledge NativeRoot into the global installation. `graphit_hub_install` installs a FILE artifact with explicit remote selection and either PROJECT/binding or global cache scope. Do not pass AST/Knowledge to the FILE installer or invent a PROJECT to stand for global installation. An obvious requested fit can be announced and installed; ask only when a material choice remains. Installation does not authorize execution of runnable content.
5. `graphit_hub_list` lists installed FILE metadata in its explicit PROJECT or global-cache scope; it is distinct from available remote search. Read installed FILE text with `graphit_hub_content` and its `installed` selection. A directory needs the selected relative `path`; omitting it does not request every file. Explicit `remote` content is a separate request-owned download. Neither route serves AST or Knowledge corpora. For Native contexts, read the module skill and its advertised installed-context/schema tools, then use the exact returned context identifier without inventing a checkout path.

Pass only fields advertised by each tool; do not add unadvertised `type`, `project_id` or legacy selectors to strict Hub payloads. Top-level `ai_optimized` is an optional strict boolean for structured MCP output: omitted/`true` selects TOON text without duplicate JSON `structuredContent`; `false` selects JSON for machine consumers. Follow pages while the decision needs coverage, without retaining entire corpora. A bounded miss, exhausted authorized inventory and service/authentication failure have different meanings. Report the covered scope and useful next action; a miss never proves global nonexistence.

## State changes

For an explicitly selected canonical local instruction directory, use the advertised Runtime tool `graphit_hub_install_local` with source_dir, producer, artifact_type (agent/skill/command/workflow/rule/mcp/language/power), full id and literal version. Omit consumer project_dir in a project-bound Root session or when a direct daemon call has exactly one checkout/version. Supply project_dir for an explicit checkout and project_version when selecting a specific retained version. It requires current administrative PROJECT authority; a Role or Browser identity cannot substitute. This records LocalLink provenance and uses a checkout-owned copy. Reapply after edits; omitted alias/entry/mode preserve the current selection. Existing PROJECT lifecycle removes the projection while preserving the source. This is not authored discovery or a global install.

`graphit_hub_sync` reapplies the selected scope's installed Hub artifacts from their recorded origins and exact versions, including authored local sources. `graphit_sync` composes global/PROJECT Hub reconciliation with native Graphit skills, agents, Coordinator, hooks and MCP. Both require administrative Runtime authority, preserve user changes as explicit conflicts and report partial effects. Use them only when publication reconciliation is needed; they do not wait for background index completion.

`graphit_hub_update` updates one selected FILE installation, or the target's remote installations when selection is omitted; local authored entries remain unchanged. It can select newer remote releases, unlike sync. Preserve the actual producer, origin and destination selection. Publishing is a separate explicit action through the advertised FILE or Native publisher schema; discovery or installation does not authorize publication.

Remote Broker catalog retraction uses `graphit_hub_unpublish` with explicit provider, producer, artifact_type, full id and target. Select `target: {kind:"version", version:"literal-release"}` (optional current expected_sha256), or explicitly `target: {kind:"artifact"}` for all versions observed in the current catalog. It has no local PROJECT, binding or source selector. Current Runtime/Local HubWrite and Broker namespace authority are required; a discovery read or installed cache is not authority. Removing latest leaves it unset; no replacement is inferred. Payloads, local sources and installations are preserved. Keep the returned retraction and any late error outcome; inspect the original selection after uncertain or oversized delivery instead of blindly retrying. An empty error payload under a tiny output limit also requires inspection of that original selection.

PROJECT FILE lifecycle uses `graphit_hub_remove` and `graphit_hub_forget` with `scope: project`, full artifact ID, kind, PROJECT/version and binding. Optional artifact version is exact. These local operations require current administrative authority but no live remote provider or source cache. Remove preserves foreign data. Forget detaches the selected metadata, returns the forgotten entry and preserves physical files; it accepts only PROJECT. Returned paths grant no deletion authority.

Remove additionally accepts explicit `scope: global_cache` or `scope: global_native` with a required exact artifact version, without PROJECT/binding fields. Global removal detaches registry metadata and preserves cached payloads and other versions. GlobalNative requires its current Native installation authority, independently of remote HubRead/STS.

A failed mutation reports its actual effect as NotApplied, MayHaveApplied or Applied. Physical changes can precede a failed metadata save. Inspect the selected metadata and affected files before explicitly running the normal operation again; an ordinary retry can conflict with files already created. There is no automatic rollback or saved filesystem operation to resume. Preserve user changes, including foreign files whose bytes happen to match. Use Forget when the authorized purpose is to detach metadata while keeping files.

Use currently advertised type/layout and configuration schemas when authoring or configuring artifacts; do not guess destinations. `graphit_config_get`/`graphit_config_list` inspect keys, and `graphit_config_set`/`graphit_config_unset` change them within the authorized work. `graphit_cluster_get`/`graphit_cluster_set`/`graphit_cluster_unset` handle project grouping.

Record resolved project, producer, artifact identity, concrete version and consequential decisions in Task. Knowledge keeps contracts; Memory keeps reusable operating decisions. Reference evidence instead of copying artifact bodies or saving host-specific roots.
